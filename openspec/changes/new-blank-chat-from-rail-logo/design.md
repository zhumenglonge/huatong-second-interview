# 设计方案

## 背景

页面已经渲染 `Conversation`、`InputBar`、`Sidebar` 和 `CanvasView`。客户端任务 store 已有 `newTask()` 状态转换，可关闭当前事件流并清理选中任务的客户端快照。当前 `IconRail` 中的 Logo 是不可交互的 `div`，而页面级视图状态由 `app/page.tsx` 在本地维护。

## 目标 / 非目标

**目标：**

- 让 Logo 成为开始项目级空白问答会话的一键入口。
- 复用现有客户端状态转换，避免新增服务端接口。
- 确保切换后显示会话流视图，包括切换前处于任务画布的情况。
- 保留任务历史和后台执行。

**非目标：**

- 取消、删除或修改正在运行的任务。
- 改变项目选择或任务持久化逻辑。
- 重设计输入框、会话协议或任务画布。

## 设计决策

1. **使用现有的 `newTask()` store action。** 该 action 已经会关闭 SSE 连接，并重置 `currentId`、会话块、产物、状态、错误和连接记录。新增 reset action 会造成逻辑重复，并增加状态不一致风险。

2. **从 `app/page.tsx` 向 `IconRail` 传入回调。** 页面持有 `view` 状态，因此回调可以在一次用户操作中调用 `newTask()` 并将视图设置为 `conv`。全局路由 URL 或自定义浏览器事件会增加间接层，但本需求并不需要真正的页面导航。

3. **使用原生 button 作为 Logo。** 原生 button 默认提供键盘激活和聚焦语义。除补充按钮样式重置与焦点样式外，可保留现有的 B 标记和 rail 视觉样式。

4. **不取消正在运行的任务。** UI 切换只改变当前客户端选中状态；已有任务继续持久化，后台运行继续进行，从而满足保留任务历史并避免破坏性副作用的要求。

## 风险 / 权衡

- [风险] 用户可能离开正在运行的任务，并暂时看不到其实时视图。→ [缓解] 保留任务列表入口并允许重新打开；在测试和 UI 语义中明确该操作不会取消任务。
- [风险] 浏览器默认按钮样式可能改变 Logo 外观。→ [缓解] 在现有 Logo CSS 中重置边框、字体、内边距和光标样式，并增加清晰的焦点样式。

## 迁移计划

不需要数据迁移或 API 发布。部署客户端变更后，验证鼠标和键盘激活；如果回归测试失败，则回滚组件、页面和 CSS 变更。
