# Design

## Context

当前 `RightPanel` 始终渲染并固定占据 300–520px 宽度；模块可通过各自标题栏的关闭按钮从内容列表中移除，但全部移除后仍留下空白栏和底部恢复条。中栏头部目前没有布局控制入口。

## Goals / Non-Goals

**Goals:**

- 建立一个由中栏“布局”入口打开的模块配置弹层。
- 让四个模块默认关闭，并让开关变更立即反映到右侧布局。
- 让右侧面板在有模块时占据空间、无模块时完全不占空间。
- 保留现有模块内容、模块内部展开/折叠和面板宽度调整行为。

**Non-Goals:**

- 不改变任务、产物、计算作业或笔记的数据来源。
- 不新增服务端接口或持久化用户账号级布局偏好。
- 不重做左侧项目侧栏的折叠逻辑。

## Decisions

### 1. 在页面层持有整体布局状态

由页面层维护 `rightPanelOpen`/可见模块集合，并将布局控制回调传入中栏头部和 `RightPanel`。整体展开状态由“至少一个模块可见”派生，避免 `RightPanel` 自己通过 DOM 内容推断是否应占宽。

替代方案是继续让 `RightPanel` 内部管理所有状态，但这会使中栏布局无法知道右栏是否应占空间，也难以让顶部布局按钮读取统一状态。

### 2. 使用即时生效的布局弹层

布局按钮打开一个轻量弹层；每个模块使用带 `role="switch"` 或等价语义的开关。切换开关直接更新共享状态，不设置“应用”按钮，因此用户能立即看到右栏展开、模块增删和中栏宽度变化。

### 3. 将模块可见性与内容展开状态分离

保留 `RightPanel` 现有的 `open` 状态表示模块内容展开/折叠，新增共享的可见性状态表示模块是否出现在面板中。关闭模块不销毁其折叠状态；再次打开时沿用上次状态。

### 4. 让 CSS 参与布局而非渲染空壳

当没有可见模块时，不渲染或折叠 `tracker-panel` 的布局宽度，使 flex 中的 `main-area` 自动扩展。面板重新出现时恢复用户最后一次调整的宽度，并使用短时宽度/间距过渡减少跳变。

### 5. 保留面板宽度的本地记忆

继续使用现有 `right-panel-w` localStorage 值保存拖拽宽度；可见模块和面板开关属于当前工作区会话状态，默认全部关闭，不引入新的服务端持久化。

## Risks / Trade-offs

- [状态分散] 页面层与 `RightPanel` 之间的状态边界不清会产生不同步。→ 将可见性和布局开关统一由页面层控制，`RightPanel` 只消费状态并报告模块内部交互。
- [小屏空间不足] 右栏展开后可能压缩会话内容。→ 复用现有 300px 最小宽度和响应式断点，布局开关可立即关闭模块释放空间。
- [刷新后体验变化] 默认关闭意味着刷新后不会自动恢复上次模块选择。→ 在首版明确采用默认关闭；仅保留现有面板宽度记忆。

## Migration Plan

1. 增加布局状态和中栏布局入口，默认所有模块关闭。
2. 将 `RightPanel` 的模块可见性改为由页面层传入，并移除底部恢复栏作为主要恢复入口。
3. 增加交互与可访问性测试，覆盖首开、即时开关、最后模块关闭和宽度保持。
4. 如需回滚，恢复始终渲染右栏及现有模块恢复条，不涉及数据迁移。
