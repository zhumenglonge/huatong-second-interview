# 设计方案

## 上下文

当前页面使用本地 `MainView` 管理会话流和任务画布，`Sidebar` 负责项目及任务导航。任务 store 已通过 `refreshTasks` 加载当前项目范围内的 `TaskRow[]`，任务选择负责恢复快照并重新连接 SSE，因此本变更复用这些边界，不新增第二套任务查询或持久化模型。

当前侧栏包含“等待输入”和“最近”两个嵌套任务分组，但只有分组拥有本地展开状态。任务标题左侧箭头错误绑定到了 `newTask`，搜索和查看全部控件没有处理函数。参考 Biomni 页面，“查看全部”会在主区域展示带搜索和状态筛选的项目任务表格。

## 目标与非目标

**目标：**

- 将任务区域折叠、新建任务、侧栏过滤和完整总览拆分为清晰且互不冲突的交互。
- 确保所有任务读取和选择都受 `activeProjectId` 约束。
- 增加主区域任务总览，同时不破坏现有会话流、任务画布、SSE、重试、取消和后台执行。

**非目标：**

- 不新增数据库表、任务持久化字段或服务端搜索接口。
- 不实现任务重命名、删除、批量操作、分页或跨项目总览。
- 不重设计任务画布或右侧结果面板。

## 设计决策

1. 增加第三种主视图 `overview`，在主区域渲染任务总览；不使用弹层，以匹配参考页面并容纳长列表。
2. 侧栏和总览都复用 store 的 `tasks` 数组，在已加载的当前项目任务上执行客户端过滤，避免重复请求。
3. 任务区域新增 `tasksOpen`；`TaskGroup` 保留自身 `open`；云盘继续使用 `cloudOpen`。父级折叠不重置子分组状态。
4. 使用独立的任务折叠按钮、新建任务按钮、搜索按钮和“查看全部”按钮，并提供 `aria-expanded` 或无障碍标签。
5. 总览任务行调用现有项目感知 `selectTask`，再切换到会话流，复用快照加载和 SSE 订阅。
6. 用 `updatedAt` 显示最近活动、`createdAt` 显示创建时间，状态筛选使用现有任务状态枚举。

## 风险与权衡

- [风险] 任务很多时客户端过滤可能变慢。→ [缓解] 原型阶段使用已加载列表，规模扩大后再引入服务端分页。
- [风险] 第三种主视图影响现有切换逻辑。→ [缓解] 集中管理视图切换，并确保任务选择始终返回 `conv`。
- [风险] 搜索框占用侧栏高度。→ [缓解] 继续使用任务区域滚动容器。

## 迁移方案

无需数据迁移。完成客户端视图、侧栏控件和测试后验证项目切换、任务选择和 SSE；回滚只需撤销这些客户端变更，任务 API 和持久化数据保持兼容。
