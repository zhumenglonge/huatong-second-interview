# Design

## Context

当前页面是 Next.js 客户端工作台，主要交互集中在 `app/page.tsx`、侧栏、会话输入区、布局弹层和右侧追踪面板。样式集中在 `app/globals.css`，任务执行和 API 不属于本次改造范围。详见 proposal.md 与对应规格增量。

## Goals / Non-Goals

**Goals:**

- 在不改变任务状态机和 API 的前提下，为工作台增加统一的语言与主题偏好。
- 将偏好状态应用到所有主要用户可见界面，并在刷新后恢复。
- 让右侧信息面板首次进入即可提供任务状态与结果上下文，同时保留用户自主收起能力。
- 让浅色和深色主题下的输入框、卡片、弹层、画布周边控件和状态颜色具有一致对比度。

**Non-Goals:**

- 不改变 Agent、SSE、SQLite、任务 API 或数据模型。
- 不翻译模型名称、技能名称、文件名和用户/Agent 生成内容。
- 不在本次变更中重做移动端布局或新增帮助、账号、云盘业务能力。

## Decisions

### 1. 使用轻量的本地 UI 偏好层

新增一个前端偏好模块，集中维护 `locale` 与 `theme`，通过 `localStorage` 持久化，并由页面顶部控件更新。选择轻量字典而不是引入完整 i18n 框架，是因为当前只有中英文两种语言、没有服务端翻译需求，且可以避免增加依赖与路由复杂度。

### 2. 采用显式文案字典并逐步替换硬编码文案

页面级、布局级、输入区、任务总览和侧栏文案从同一字典读取。动态任务标题、Agent 回复、产物名称和模型/技能专有名词不经过翻译。这样可以避免语言切换只改变顶部按钮，却留下局部英文或中文。

### 3. 主题通过 CSS 变量统一切换

在根元素上设置主题标记，由 `globals.css` 提供背景、面板、边框、文字、输入和状态颜色变量。对于现有硬编码白色或浅色背景，优先替换为语义变量；对第三方 React Flow 控件仅覆盖工作区周边和必要控件，不修改画布核心逻辑。

### 4. 右侧面板默认可见但仍可关闭

页面初始布局状态将四个模块设为可见，RightPanel 的四个内容区默认展开。布局开关仍然控制“是否显示”，面板内部折叠状态继续独立维护，以符合修改后的 `right-panel-layout` 规格。

### 5. 删除冗余 backend 标识

移除主区顶部的 `real QoderCN Agent backend` 文案；保留产品名、视图切换和偏好控件，使标题区更紧凑并减少技术实现噪音。

## Risks / Trade-offs

- [风险] 硬编码颜色散落在旧样式中，深色主题可能出现局部白底或对比度不足。→ [缓解] 先覆盖核心工作区路径并通过浅/深主题截图检查，再搜索剩余硬编码背景色。
- [风险] 首次默认打开四个面板会挤压会话区。→ [缓解] 保留可拖宽、可关闭和可折叠能力；默认宽度限制在现有范围内。
- [风险] 语言切换过程中客户端首次渲染可能出现短暂默认语言。→ [缓解] 在客户端挂载后读取持久化偏好，并避免把偏好写入服务端任务数据。
- [风险] 新字典覆盖不完整会留下中英混用。→ [缓解] 对用户可见静态文案做全局检索，补充测试或人工检查主要视图。

## Migration Plan

1. 添加偏好状态与字典，并接入页面、布局、侧栏、输入区和总览。
2. 将右侧面板初始可见性和内部展开状态调整为全开。
3. 替换硬编码文案与主题相关颜色，移除 backend 标识。
4. 运行类型检查、单元测试和生产构建，并在两种语言/两种主题下检查主会话流、画布和右侧面板。
5. 若出现回归，可回滚 UI 偏好模块和对应样式，不影响任务 API 与持久化数据。
